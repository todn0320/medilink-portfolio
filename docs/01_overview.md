# 01. 프로젝트 개요 & 배경

## 왜 이 서비스가 필요한가?

### 소비자가 직면한 3가지 핵심 문제

**① 외형만으로는 구분 불가능**
유사한 모양·색상의 알약이 너무 많아 사용자가 육안으로 구분하기 사실상 불가능합니다. 전문지식 없이는 동일해 보이는 알약이라도 성분과 용량이 전혀 다를 수 있습니다.

**② 병용 위험을 스스로 파악하기 어려움**
처방약·일반의약품·건강기능식품을 함께 복용할 때 발생하는 병용금기·성분 중복 위험을 일반인이 확인하기 어렵습니다. 처방전에도 표기되지 않는 경우가 많고, 각각 따로 먹으면 괜찮더라도 병용 시 위험한 조합이 존재합니다.

**③ 정보 분산**
처방약·OTC·건강기능식품 정보가 각각 다른 곳에 흩어져 있어 통합 관리가 불편합니다.

## 핵심 설계 원칙

### "결정은 공식 데이터가, 보조는 AI가"

| 역할 | 담당 | 데이터 소스 |
|---|---|---|
| 병용금기 경고 | **공식 데이터 (결정 엔진)** | 식약처 DUR 품목·성분 |
| 의약품 정보 제공 | **공식 데이터 (결정 엔진)** | 의약품 허가정보·e약은요 |
| 이미지 Top-5 후보 생성 | AI 보조 계층 | YOLOv8 + ResNet |
| 각인 텍스트 추출 | AI 보조 계층 | Azure OCR |
| DB 매칭 후보 재정렬 | 룰 기반 | Oracle DB 4-way JOIN |
| 자연어 설명 생성 | AI 보조 계층 (근거 없으면 생성 보류) | RAG + GPT-4o-mini |

**AI 환각(Hallucination) 방지 전략**: 근거 문헌(DUR 데이터)이 확인된 정보만 출력하며, 검색된 청크가 없는 경우 답변 생성 자체를 차단하는 로직을 구현했습니다.

## 유사 서비스 대비 차별점

| 서비스 | 주요 특징 | MediLink와의 차이 |
|---|---|---|
| 필라이즈 | 영양제 성분 분석·중복 체크 | 마케팅 추천 → MediLink는 DUR 기반 의학적 안전성 우선 |
| 파프리카케어 | 처방전 OCR 기반 복약 관리 | 단순 기록 → MediLink는 RAG 기반 정교한 복용 가이드 |
| 스마트DUR | 전문가용 DUR 체크 | 고전적 UI → MediLink는 LLM 기반 친절한 설명 제공 |
