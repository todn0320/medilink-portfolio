# 초기 브레인스토밍 & 아이디어 발굴

## 프로젝트 방향 결정 과정

### 검토한 초기 아이디어들 (2026.02.24)

팀원들이 제안한 다양한 아이디어 중 최종 선택 과정:

| 아이디어 | 검토 결과 |
|---|---|
| 차량 얼굴인식 초소형 카메라 | 하드웨어 필요 → 소프트웨어 우선으로 방향 전환 |
| 노인 스마트 양말/패치 | 하드웨어 필요 → 제외 |
| 고독사 방지 안부 서비스 + 치매 감지 | 기존 서비스와 유사 |
| 스마트 변기 (대변 AI 분석) | 이미 존재 (스탠퍼드대 등) |
| 병원비 사전 체크 앱 | 시중에 존재 |
| **약품 성분·효능 기반 복약 관리** | ✅ **최종 선택** |

### 선택 이유
1. **명확한 공공데이터 존재**: 식약처 공공데이터포털에서 충분한 데이터 확보 가능
2. **실질적인 사회적 문제**: 노인·만성질환자의 다약제 복용 위험 증가 추세
3. **AI 활용 포인트 명확**: 이미지 인식 + RAG + 병용금기 경고 엔진
4. **Azure 서비스 적극 활용 가능**: Vision, OCR, AI Search, OpenAI 등 다수

## 서비스 차별화 전략

### "공식 데이터 = 결정, AI = 보조" 원칙 수립

기존 유사 서비스들이 AI 추천을 전면에 내세우는 반면, MediLink는 식약처 DUR이라는 공신력 있는 데이터를 판단의 절대 기준으로 삼고 AI는 설명 생성 보조 역할만 수행합니다.

이 원칙은 다음 문제를 해결합니다:
- AI 할루시네이션 위험 (의료 정보에서 치명적)
- 의료법 준수 (진단·처방 행위 배제)
- 사용자 신뢰 확보 (근거 출처 명시)

## 확장 아이디어 (MS 발표 후 브레인스토밍, 2026.03.20)

### 단기 확장
- **의료진 공유**: 복약 현황 PDF 생성 → QR코드로 의사에게 공유
- **가족 계정**: 부모님 약 대신 관리

### 중기 확장
- **음성 검색**: Azure AI Speech → "이 약 뭐야?" 음성으로 검색
- **처방전 OCR**: Azure Document Intelligence로 처방전 촬영 → 자동 복약 등록
- **복약 예측 AI**: Azure Machine Learning으로 "이 사용자가 약을 제때 안 먹을 확률" 예측

### 장기 확장
- **FHIR 연동**: 처방이력 연동 (Health Data Services)
- **건강기능식품 성분 궁합**: 비타민 C + 철분 = 흡수 증가 등 근거 기반 추천
- **다국어 지원**: Azure AI Translator로 외국인 환자 대상 서비스
